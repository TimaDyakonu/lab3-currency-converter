## 2. Выбор источника данных

Выбран **официальный XML Национального банка Молдовы**
(`https://www.bnm.md/en/official_exchange_rates?get_xml=1&date=DD.MM.YYYY`).

Причины:

- это официальный курс, действующий для расчётов на территории Молдовы;
- не требуется регистрация и API-ключ, лаборатория воспроизводится на любой машине;
- формат XML разбирается стандартными средствами .NET (`System.Xml.Linq`);
- курс публикуется только в рабочие дни, что создаёт настоящие пограничные случаи (выходные, праздники, пустой ответ),
  которые требуется обработать по заданию.

Минус выбора: JSON-эндпоинта нет, и курсы заданы к молдавскому лею (MDL), поэтому конвертация между двумя
иностранными валютами идёт через MDL с учётом поля `Nominal`.

## 4. Что агент собрал корректно с первой попытки

- Структура решения из трёх проектов точно по плану: `CurrencyConverter.Core`, `CurrencyConverter.App`, `CurrencyConverter.Tests`.
- Логика отделена от интерфейса: парсер, конвертер, валидатор и кэш находятся в Core за интерфейсами
  (`IRatesProvider`, `IRateCache`, `IBnmXmlParser`, `IInputValidator`), в WPF подключены через MVVM.
- Расчёт выполняется на `decimal`, учитывается `Nominal`, кросс-курсы идут через MDL.
- Пограничные случаи из задания: пустой ответ источника с поиском курса за предыдущие дни (до 7), отсутствие сети
  с переходом на кэш, некорректный ввод, одинаковые валюты, запятая и точка как разделитель.
- Кэш в JSON-файле в `%LOCALAPPDATA%\BnmCurrencyConverter\rates_cache.json`, переживает перезапуск.
- Сборка без ошибок и предупреждений, **80 из 80 тестов проходят**, приложение запускается.
- Ручная проверка по списку из задания (конвертация в обе стороны, кросс-курс, плохой ввод, одинаковые валюты,
  работа без сети после перезапуска) прошла без замечаний.

## 5. Где агент ошибся и что пришлось исправлять

В **исходный код агента вручную не вносилось ни одной правки**. Все исправления касались состава репозитория.

| № | Проблема | Последствие | Исправление |
|---|----------|-------------|-------------|
| 1 | Агент создал сразу два файла решения: `CurrencyConverter.sln` и `CurrencyConverter.slnx` | В корне команды `dotnet build` и `dotnet test` падают с ошибкой MSB1011 (найдено несколько файлов решения), а в README описаны именно они | Вручную удалён `.slnx`, оставлен `.sln` |
| 2 | Не создан `.gitignore` | В коммит попали бы каталоги `bin/` и `obj/` | Вручную добавлен стандартный `.gitignore` для .NET (`dotnet new gitignore`) |
| 3 | Агент написал тесты на этапе реализации, хотя по требованиям Git они выполняются отдельным этапом в отдельной ветке | Нарушение процесса: нужно было развести реализацию и тесты | Проект тестов временно убран из решения на ветке `implementation`, добавлен обратно на ветке `tests` |
| 4 | Агент отметил все 39 задач в `tasks.md` как выполненные | Отметки поставлены самим агентом, без независимой проверки | Выполнение проверено вручную: сборка, 80 тестов, ручной прогон приложения |

Замечания, найденные при сопоставлении кода со спецификацией, вынесены в раздел 6.

## 6. Соответствие кода спецификации

Код сопоставлен с функциональными требованиями `FR-001 ... FR-016` из `spec.md`.

| Требование | Статус | Комментарий |
|-----------|--------|-------------|
| FR-001 интерфейс | выполнено | поле суммы, два списка валют, кнопка, результат, дата и источник |
| FR-002 кнопка неактивна до заполнения | **частично** | см. расхождение A |
| FR-003 источник BNM XML | выполнено | шаблон адреса в `BnmConstants.UrlTemplate` |
| FR-004 учёт `Nominal` | выполнено | курс нормализуется к одной единице |
| FR-005 обе стороны и через MDL | выполнено | формула `сумма * курс_источника / курс_цели` |
| FR-006 округление до двух знаков | выполнено | проверено вручную и тестами |
| FR-007 одинаковые валюты | выполнено | результат равен сумме |
| FR-008 запятая и точка | выполнено | |
| FR-009 некорректный ввод | выполнено | пусто, буквы, ноль, минус; конвертация не выполняется |
| FR-010 нет сети | **частично** | см. расхождение B |
| FR-011 пустой ответ, выходные | выполнено | см. замечание C |
| FR-012 нет ни сети, ни кэша | выполнено | понятное сообщение, приложение не падает |
| FR-013 сохранение кэша | выполнено | пишется после каждого успешного ответа |
| FR-014 нет выдуманных курсов | выполнено, с замечанием D | |
| FR-015 дата и источник | выполнено | всегда в интерфейсе |
| FR-016 тесты | выполнено | `dotnet test`, 80 тестов |

### Расхождения и замечания

**A. FR-002: «неактивна, пока не заполнено валидно».** Кнопка проверяет только то, что поле суммы не пустое и обе валюты
выбраны. Корректность суммы (буквы, ноль, минус) проверяется уже после нажатия, и пользователь видит сообщение об ошибке.
Это совпадает с User Story 3 (сценарий 2), но строже, чем формулировка FR-002. Спецификация внутренне двусмысленна, агент
выбрал один из двух вариантов и сообщений о выборе не оставил.

**B. FR-010: «предлагает курс из кэша».** Спецификация (и текст задания) говорит, что приложение *предлагает* работать с последним
сохранённым курсом. Агент реализовал автоматическое переключение на кэш с явным сообщением и датой курса, без
подтверждения пользователя. Результат не вводит в заблуждение, но поведение отличается от слова «предлагает».

**C. Поиск курса за предыдущие дни.** В `spec.md` (FR-011) при пустом ответе используется «последний сохранённый курс», а в
`plan.md` добавлен перебор до 7 предыдущих дней в сети. Код следует плану. Это расхождение между самими документами
Spec Kit, а не ошибка агента; оно показывает, что план расширил спецификацию.

**D. Возможный дефект обработки ошибок (найден при чтении кода, не воспроизводился).** В `BnmRatesProvider.GetLatestAsync`
вызов `_cache.SaveAsync` расположен внутри блока `try` с общим `catch (Exception)`. Если запись кэша на диск завершится
ошибкой (например, нет прав или нет места), такая ошибка будет классифицирована как сетевая («Transport error»), цикл прервётся и
вместо только что полученного свежего курса будет использован старый кэш. Спецификация требует, чтобы сбой кэша не влиял
на работу; сейчас он может скрыть актуальный курс. Исправление не вносилось, чтобы не менять код агента после приёмки.

**E. Язык интерфейса.** Спецификация написана на английском и не задаёт язык интерфейса, поэтому все надписи и сообщения
в приложении английские. Для задания это допустимо, но локализация в требования не входила.

### Общая оценка

Код соответствует спецификации по всем основным сценариям: все 16 требований выполнены, два (FR-002, FR-010) реализованы с отклонением от
буквы формулировки. Значительная часть расхождений вызвана неоднозначными формулировками в самих спецификациях, а не
ошибками агента. Это главный вывод работы: качество результата определяется точностью требований.

## 7. Работа с Git

- Отдельная ветка на каждый этап: `specs`, `implementation`, `tests`, `report`.
- Слияние в `main` только через Pull Request: спецификации, реализация, тесты, отчёт.
- Спецификации закоммичены раньше реализации.
- Сообщения коммитов описывают суть изменения, история отражает процесс по шагам.

Запуск проекта и тестов описан в [README.md](README.md):

```bash
dotnet build
dotnet test
dotnet run --project src/CurrencyConverter.App
```
